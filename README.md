# 3v3 Fixture Generator

Create fair, organised and balanced small-sided games in seconds. A free, open-source, static web app — everything runs in the browser, with no accounts and no data leaving your device.

## How it works

The app walks you through a short setup, then generates the session:

1. **Squads & players** — add up to 4 squads and set how many players are in each. Rename them to your own club or team names and optionally paste in player names.
2. **Session settings** — game duration, rest time, an optional pitch-change buffer, total session length, start time and number of pitches.
3. **Spare players & options** — how spares are handled, team size (1v1 to 11v11), match-up format, whether team-mates rotate, and pitch formats.
4. **Generate** — the app builds the schedule and takes you to the results.

## Match day timer

Once fixtures are generated, a live timer appears at the top of Home and Fixtures:

- Countdown ring showing the round number and whether it is play time or a break
- Play/pause, restart, skip to the next phase, and mute
- A chime and a vibration (Android) at every change of phase; browsers cannot
  play the phone's own ringtone, so the chime is generated by the app
- Keeps the screen awake while running, where the browser supports it
- Runs off the real clock, so it stays accurate if the phone locks or you switch
  apps, and it picks up where it left off if the app is closed and reopened

The current round is highlighted in the schedule and updates as the timer moves on.

## Screens

- **Home** — start a new session, open saved setups, and jump to the current session
- **Fixtures** — the full schedule, filterable **by team** or **by pitch**, with a detail view for each match showing both line-ups and who is resting
- **Fairness** — squad and player fairness scores, a squad-by-squad comparison, and a per-player bar showing games played, rest rounds and how they compare to the squad average
- **Settings** — appearance (light/dark), saved setups, how it works, and CSV export

## Features

- 2–4 squads, 1–30 players each, with optional named player lists
- **Equal-sided teams by default** - choose one number of players per team (1 to 11) and the app shows it as NvN. Manual pitch formats are one whole number per pitch; entries like 7v5 are rejected. With Everyone plays off, every match is equal-sided and a pitch with too few players is left unused
- **Everyone plays (controlled uneven teams)** - turn it on and every present player is placed on a pitch each round. Sides may differ by at most one player (7v8, 4v3), never exceed 11, and the extra player rotates. Your match-up rule is kept unless you choose "Allow mixing squads if needed"; if it cannot fit everyone you are told why
- **Impossible sessions are refused** - a session with no valid matches never reaches the success screen and never replaces your previous session
- **Settings always match the screen** - one function repaints every control from the saved settings (drafts, templates, imports, reset), and generation stops if the screen and settings ever disagree
- **Any team size** — type any players-per-side number (max 11) (1v1 up to 11v11) or tap a quick pick
- **Short-handed games** - when a squad can't fill a full team, the last pitch plays a short game (e.g. 3v2) and the players in it rotate every round
- **Fewest games play first** (switch on the options screen) - when more players turn up than there are spaces, the players with the fewest games go on first. Each round lists who is not playing, and the schedule lists who is staying home
- **Fairness explained** - when squads of different sizes get uneven game counts, the Fairness screen says why and what to change
- **Fonts are bundled** - no requests to Google, and a Content-Security-Policy limits what the page can load
- **Unused-pitch notice** - if a pitch would sit empty, the app says so and offers a one-tap "Use all pitches" (Everyone plays)
- **Input checks** - session settings are kept within sensible limits, and imported setup files are validated before loading
- **Match-day attendance** — tap names to mark who is absent; they are left out of the fixtures. Attendance resets at the start of each new session, while squads and settings are remembered
- **Works offline** — after the first visit the whole app is cached; when you publish an update, users see a "new version ready" bar
- Configurable game time, rest time, pitch-change buffer, total session length, start time and pitches
- Spare players either rotate on as substitutes or rest between rounds
- **Everyone plays every round** (optional) - see "Everyone plays (controlled uneven teams)" above. With squad v squad or within-squad match-ups the rule is kept strictly; "Allow mixing squads if needed" is an explicit opt-in for when it cannot fit everyone
- Team-mates rotate each round or stay together for the whole session
- Match-up formats: **squad v squad** (default — a squad never plays itself), within squad, or fully mixed
- Pitch formats: automatic, manual per pitch, or "balance uneven" (equal-sided like the others; uneven teams only happen when Everyone plays is on)
- Fairness scored against the squad average, so being one game behind the busiest player doesn't read as unfair
- **Dark mode** — follows your system setting by default, with a toggle in Settings
- Save setups as templates in the browser, or export/import a `.json` file to move between devices
- The current session and timer are saved on the device, so closing the app mid-session loses nothing
- One-click CSV export of the schedule
- **Installable** — add it to your phone's home screen and it opens full screen with no browser bars; the device back button steps back through the app instead of closing it

## Project structure

```
index.html      All screens (single-page app shell)
sw.js           Service worker (offline cache) - VERSION is bumped by scripts/release.js
fonts/          Inter (SIL Open Font License, see fonts/LICENSE-Inter.txt)
tests/          Engine and interface tests - run with: npm install, then npm test
scripts/        release.js - runs the tests, then bumps the offline-cache version
.github/        GitHub Action that runs the tests on every push
manifest.json   Web-app manifest (full-screen install, icons)
icon-192.png    App icon
icon-512.png    App icon
style.css       Design tokens and styling, including the dark theme
js/engine.js    Scheduling logic (pure functions, no DOM — testable in Node)
js/app.js       Screen routing, rendering, icons and fairness scoring
images/         Drop your own photos here (see images/README.md)
```

## Adding your own images

The app ships with no photos — the interface is drawn entirely with CSS
gradients and inline SVG icons, so it works offline and loads instantly.
If you want a photo on the home screen, save it as `images/hero.jpg` and
uncomment the marked block in `style.css`. Full instructions are in
`images/README.md`.

Keep images under about 300 KB and no wider than 1600 px so the app stays fast
on mobile data.

## Installing it on your phone

Once the site is live on GitHub Pages, open it on your phone and:

- **iPhone (Safari):** Share - Add to Home Screen
- **Android (Chrome):** menu - Add to Home screen / Install app

It then launches full screen without browser chrome, and the hardware/gesture
back button moves back one screen rather than closing the app.

Note: on iPhone this only works from **Safari** — adding to the home screen from
Chrome on iOS opens in a browser tab instead.

## Running it locally

Static site, no build step:

- Open `index.html` directly in a browser, or
- Serve the folder, e.g. `python3 -m http.server 8000`, then visit `http://localhost:8000`

## Hosting on GitHub Pages

**Without the command line:**

1. Create a new **public** repository on GitHub.
2. **Add file - Upload files**, drag in `index.html`, `sw.js`, `manifest.json`, the icons, `style.css`, `README.md`, `LICENSE` and the `js` folder, then commit.
3. **Settings - Pages**, set Source to **Deploy from a branch**, pick **main** and **/ (root)**, save.
4. Your site appears at `https://<username>.github.io/<repo-name>/` within a minute or two.

**With git:**

```bash
git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin https://github.com/<username>/<repo-name>.git
git push -u origin main
```

## How the scheduler works

Each round, the engine fills every pitch with a match sized to that pitch's format, drawing players according to the match-up rule and the team-formation rule. Players who have played the fewest games so far are always prioritised, so game time evens out across the session even when squads are different sizes. Anyone left over is marked resting, and that rest feeds into who plays next. Rest time and the pitch-change buffer are both added to the gap between rounds.

## Releasing an update

1. Make your changes.
2. Run `node scripts/release.js` (needs Node 18+). It runs the tests and bumps the version in `sw.js`.
3. Upload the changed files, always including `sw.js`. Phones then show a "new version ready" bar.

Without Node, edit the `VERSION` line at the top of `sw.js` by hand (any new value works).
